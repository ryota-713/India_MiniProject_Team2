# ShopNova — デモ用ECサイト（攻撃検知の実演ターゲット）

サイバー攻撃検知システム（`../MyProject`）の発表で使う「顧客側の画面」兼「攻撃の標的」です。
Python 標準ライブラリだけで動きます。**学習用に、わざと脆弱に作ってあります。ローカル環境・ダミーデータ専用です。**

## できること

- ECサイト風のログイン画面とホーム画面（商品一覧・検索・カート）
- **SQLインジェクションの脆弱性**：`admin' OR 1=1 --` で実際にログインできる（デモ用）
- すべてのリクエストを検知システムと同じ形式で記録し、`/api/monitor/events` で配信
- 検知システムの「Live Attack Monitor」から**IP指定でリアルタイム監視**できる

## 起動

```
python ec-shop/server.py
```

http://127.0.0.1:8080 を開きます。ポートは `EC_PORT`、ホストは `EC_HOST` で変更できます。

## 管理者アカウント

| ユーザー名 | パスワード |
|---|---|
| `admin` | `admin1234` |

`EC_ADMIN_USER` / `EC_ADMIN_PASSWORD` で変更できます。これはダミーのアカウントで、
メモリ上の使い捨てテーブルに入っているだけです。本物の認証情報ではありません。

## 画面とエンドポイント

| パス | 説明 |
|---|---|
| `/login` | ログイン画面 |
| `/home` | ホーム画面（未ログインは `/login` に戻る） |
| `/logout` | ログアウト |
| `/api/monitor/events?since=N` | 検知システム向けのイベント配信（攻撃対象ではない） |
| `/health` | 稼働確認 |

## 脆弱モードについて（重要）

既定では `SHOP_VULNERABLE=1` で、ログイン照合をわざと文字列連結SQLにしています
（`server.py` の `check_login`）。これが `admin' OR 1=1 --` を通してしまう教科書的な欠陥です。

- `SHOP_VULNERABLE=0` にすると、パラメータ化クエリの安全なログインに切り替わります
  （「脆弱 → 対策後」の比較デモに使えます）。
- 脆弱モードはローカルアドレスにバインドしているときしか起動しません
  （外部公開を防ぐため、非ローカルホストでは起動を拒否します）。
- サイトは入力をDBやシェルとして**実行しません**（ログイン照合の1箇所だけが意図的に脆弱）。

## 検知システムとの連携（スキーマ）

検知システムのイベントは7項目です：
`event_id, timestamp, source, method, path, status_code, user_agent`。
ショップはこの形式で記録します。

- `source` … アクセス元IP（検知側はこの単位でブルートフォースを集計）
- `path` … ログイン試行は `/login?username=<入力ユーザー名>` の形で記録。
  これにより `admin' OR 1=1 --` が `path` に乗り、ルール **SQLI-001** が反応します。
  **パスワードは記録しません。**
- `status_code` … ログイン失敗は `401`。同一IPから5分で5回以上失敗するとルール
  **AUTH-REPEAT-001**（ブルートフォース）が反応します。

## ブルートフォース実演ツール

```
python ec-shop/attack_demo.py --target 127.0.0.1:8080 --rate 5 --count 30
```

- 1秒あたり約5回（`--rate`、上限20）、合計30回（`--count`、上限2000）のログイン試行を送ります。
- 途中で1回、SQLインジェクション（`admin' OR 1=1 --`）も送ります（`--no-sqli` で無効化）。
- **loopback / プライベートIP以外は拒否**します。自分のデモ用ショップ専用です。

## 発表の手順（例）

1. `python ec-shop/server.py` でショップを起動。
2. 検知ダッシュボード（`../MyProject`）を起動し、「Live Attack Monitor」を開く。
3. 監視対象に `127.0.0.1:8080` を入力し、「自動更新」をON。
4. 別ターミナルで `python ec-shop/attack_demo.py` を実行。
5. ダッシュボードで「SQLiログイン試行」「admin' OR 1=1 -- 試行」「失敗ログイン」の数値と、
   時間帯別の折れ線グラフ、ブルートフォース警告がリアルタイムに増えるのを見せる。
